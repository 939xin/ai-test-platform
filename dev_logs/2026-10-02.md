### 任务 3b：场景串联 ★

**做法**：整个场景**共用一个 `VariableResolver`**。每步跑完把 `extracted` 灌进 `set_extra_var()`，
下一步执行时把「全局变量 + 运行时变量」合并后当作环境变量传给 `execute_case`。

之所以不去改 `execute_case` 的签名（让它接受一个现成 resolver），是因为合并变量字典这一步不侵入：
`get_all_variables()` 返回的正是「运行时优先」的结果。少改一处引擎代码，就少一处回归风险。

**新增**（8 个文件）
- `services/scenario_runner.py` —— 串联执行循环；`fail_strategy=stop` 时剩余步骤记为 `skip`（不是消失），
  前端才能说明「为什么只跑了 2 步」
- `schemas/scenario.py` + `api/scenarios.py` —— 场景 CRUD（steps 整体替换，`step_order` 由后端按数组顺序重排）
  + `POST /scenarios/{id}/run`；**每个步骤都落一条 execution**，执行中心与测试报告里能回溯
- 前端 `api/scenario.js` + `ScenarioList.vue` + `ScenarioEditorDrawer.vue`（选用例 / 上下移 / 失败策略）
  + `RunScenarioDialog.vue`（步骤条 + 逐步查看请求/响应/断言）
- `router/index.js` + `AppLayout.vue` —— 侧栏新增「场景测试」（第 10 项）

## 任务 3b 踩的坑：URL 拼接顺序错了（引擎真 bug）

第一次跑场景验收，两项失败。看结果：

```
✅ 步骤 1 提取到变量   https://httpbin.org/get
❌ 串联生效：步骤 2 的 ${echo_url} 被解析成上一步的值   https://httpbin.org/https://httpbin.org/get
```

变量**确实被解析了**，但最终 URL 被拼成了 `https://httpbin.org/https://httpbin.org/get`。

根因在 `api_executor.build_request()`：

```python
raw_url = case["url"]                      # "${echo_url}" —— 字面量不以 http 开头
if raw_url.startswith(("http://", ...)):   # ← 判断在解析之前
    full_url = raw_url
else:
    full_url = f"{base_url}/{raw_url}"     # ← 被当成相对路径，加了 base_url 前缀
full_url = resolver.resolve(full_url)      # ← 解析发生在最后
```

**只有「URL 完全由 `${变量}` 组成」时才会暴露** —— 而这正是场景串联最典型的用法。
旧桌面版也有同样的写法，只是旧版没有场景串联，触发不到。

- 修复：**先解析变量，再判断要不要拼 base_url**
- 验收里那条断言正是为它写的，所以修完立刻转绿

> 又一次印证：**用例之间的传参链路，只有真的串起来跑一次才发现得了问题**。
