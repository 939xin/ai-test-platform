### 双向跳转怎么串的

执行详情「提缺陷」→ `/defects?open=<缺陷id>&project=<项目id>` → 缺陷页自动打开抽屉。
缺陷详情「查看执行」→ `/executions?open=<执行id>` → 执行中心自动打开抽屉。

项目 id 一起带走是必须的：光给缺陷 id，缺陷页不知道该查哪个项目。
两个页面都在打开抽屉后用 `router.replace` 把 `open` 清掉，
免得用户关掉抽屉再刷新又弹出来。

同样的 query 用法在 Day 6 的用例编辑页已经用过（`?project=29`），保持一致。

### 重复提交的处理

同一条执行只允许挂一条缺陷。第二次点「提缺陷」时后端返回 **409**，
`detail` 形如 `{"message": "该执行记录已提过缺陷 #4", "defect_id": 4}`，
前端据此提示并直接跳转到已有那条。避免同一条失败被反复点出一串重复缺陷。

## 踩的坑

### 统一报错只认字符串 detail —— 是个真 bug

`api/request.js` 的响应拦截写的是：

```js
const message = detail || error.message || '请求失败'
```

而 FastAPI 的 `detail` 有三种形态：

| 场景 | 形态 |
|---|---|
| 业务异常自己抛的 | 字符串，如 `"缺陷不存在"` |
| **422 参数校验** | **数组**，每项 `{ loc, msg }` |
| 需要带额外数据时（这次的 409） | 对象，`{ message, defect_id }` |

后两种塞进 `ElMessage.error()` 就是 `[object Object]`。422 那条是**本来就存在**的
隐患 —— 之前任何一个表单校验失败，前端弹的都是这串乱码，只是没人细看。
这次一并修掉：按三种形态统一压成一句可读文案。

# 第二轮 · 全站 JWT 校验（Day 8）

同一天的第二轮。从第一轮末尾的清单里挑，按优先级选了 **全站接口 JWT 校验** ——
它是 Day 3 就记下的欠账，而且是安全问题，优先级最高。

## 动手前先纠正了一个写在项目里的错误认知

`CHANGELOG` 和 `CLAUDE.md` 都把这件事记成「登录能签发、前端也带上了，但后端没有一处 `Depends`」，
听着像是补个依赖就完事。**实际不是。**

查了两件事：

| 查什么 | 结果 |
|---|---|
| `api/health.js` 里导出的 `login()` 有没有调用点 | 没有，一处都没有 |
| 全前端有多少处 `localStorage` | **1 处，而且是 `getItem`（读）—— `setItem` 一个都没有** |

再加上没有 `stores/` 目录、没有 `Login.vue`、路由里没有 `/login`，
结论是：**前端根本没有登录这条路**。所以只补后端校验的话，改完那一刻整个 UI 就打死了 ——
每个页面都会 401，而且用户没有任何办法登进来。

这条是这次改动从「1~2 个文件」变成「9 个文件」的真正原因。

## 后端（4 个文件）

**`api/deps.py`（新）** —— `get_current_user`。没带 token / 伪造 / 过期 / `sub` 对应用户已被删除，
四种情况统一 401 并带 `WWW-Authenticate: Bearer`。

第四种是刻意加的：光验签不够，用户被删掉后旧 token 在过期前仍然验得过。

用 `HTTPBearer(auto_error=False)` 而不是手解析 header —— 顺带让 `/docs` 上出现 Authorize 按钮，
调试接口时不用手搓 curl。

**`main.py`** —— 守卫**不挂在各个路由函数上**，而是 `include_router(..., dependencies=guard)`：

```python
guard = [Depends(get_current_user)]
app.include_router(cases.router, prefix="/api", tags=["cases"], dependencies=guard)
```

好处是 11 个路由模块**一行都不用改**，豁免清单也只在这一个文件里看得见。
代价是新增路由模块时得记得挂上，否则它默认是裸奔的 —— 这条已写进 `CLAUDE.md`。

**`api/reports.py`** —— 拆成 `router`（受保护）+ `public_router`（豁免）。

## 豁免清单是推出来的，不是拍的

四条豁免各有理由，其中报告那两条是**被迫的，不是偏好**：

| 路径 | 为什么豁免 |
|---|---|
| `/api/auth/login` | 还没登录，此时必然没有 token |
| `/api/health` | `start.bat` 和前端登录前就要探活 |
| `/api/demo/*` | Selenium 浏览器直接打开 |
| `/api/reports/{filename}`<br>`/api/reports/screenshots/{path}` | 浏览器 `window.open` / `<img src>` 直接导航 |

最后一条值得展开：报告 HTML 里的截图是**浏览器渲染报告时自己发出的请求**，
不是前端代码发的。所以任何前端写法都带不上 `Authorization` 头 —— 这是浏览器导航的固有限制，
不是代码写得好不好的问题。全前端只有 3 个地方是这种 URL（grep 确认过：
`ReportList.vue` 的 `window.open`、`ExecutionResult.vue` 的 `:href` 和 `<img :src>`），
正好就是这两条路由。

安全性上没有裸奔：这两条路由各自都有 `../` 越界防护（`_safe_report_path` /
`_safe_screenshot_path`），不依赖鉴权兜底。

## 前端（5 个文件）

**`api/session.js`（新，20 行）** —— 登录态存取单独一层。
多出这个文件的理由：`request.js`（401 时清登录态）和 `auth.js`（登录时写登录态）都要碰
localStorage，而 `request.js` 不能反过来 import `auth.js`，否则是 `auth ↔ request` 的循环引用，
axios 实例初始化时会拿到 `undefined`。不拆的话就得在两个文件里各写一份 key 字符串。

**`views/LoginView.vue`（新）** —— 在 `AppLayout` 之外，独立全屏。没登录的人不该看到侧栏菜单。
配色全部走设计令牌，组件只用 Element Plus。

**`router/index.js`** —— 双向守卫：没 token 进受保护页 → 踢回登录页并把原地址记进
`redirect`；已有 token 还去登录页 → 直接送进项目页（否则登录后点后退又回登录页）。
`redirect` 只接受 `/` 开头且非 `//` 开头的值，挡掉开放重定向。

**`components/AppLayout.vue`** —— 顶栏原来是个写死的「鑫」字头像，现在显示用户名 + 退出登录。

**`api/request.js`** —— 401 拦截。

## 踩的坑

### 1. 登录接口自己的 401 不能按「会话过期」处理

后端密码错返回的是 401，跟会话过期的状态码撞了。第一版没区分，
结果**在登录页输错密码，弹的是「登录状态已失效，请重新登录」**，用户完全摸不着头脑。

判据是请求 URL：`error.config.url` 里含 `/auth/login` 就跳过失效处理，走普通报错路径。

### 2. 会话过期的提示根本来不及渲染

第一版是 `ElMessage.warning()` 之后**立刻** `window.location.href = '/login'`。
实测：页面直接卸载，**那句提示一次都没出现过** —— 用户莫名其妙就落到登录页了。

改成跳转前留 800ms。这类问题只有真跑一遍浏览器才看得见，`npm run build` 是查不出来的。

### 3. 多个并发 401 会连着弹一串

一个页面往往好几个请求同时在飞，token 失效时会连着回来一串 401。
加了个 `expiredHandled` 标记，只提示一次、只跳一次。
登录成功后是整页刷新，模块重新加载，标记自然复位。

新增的 4 项边界里，有 3 项是钉「不带 token 真会被拦」的。这条很重要：
其余 100 多项全靠 `SESSION` 的 token 通过，**万一守卫根本没挂上，整份验收会因为误放行而全绿** ——
所以必须单独证明拦截确实生效。

`verify_all.py` 的改法是加一个 `requests.Session()`，登录后把 token 塞进它的 header，
再把 104 处裸调机械替换成 `SESSION.*`。只有登录那两次刻意留用裸 `requests`，
免得把上一次的 token 带进登录请求。
