## 后端

**`services/ai_prompts.py`（新）** —— 提示词写成常量，不散在路由里。

关键的一条是 `ASSERTION_RULES`：**把断言引擎真正实现的那几组显式列给模型**
（`status_code` 取 eq / ne、`response_time` 取 gt / lt、`response_body` 取
eq / ne / contains / regex）。不写这段，模型会编出 `body_contains`、`jsonpath` 之类
看着很合理、但引擎里根本没实现的断言，用户拿到手一跑就报错。

**`services/ai_client.py`（新）** —— 只做三件事：发请求、重试、把返回文本解析成 JSON。

- **超时 60 秒**：整批生成偶尔要几十秒，给足余量
- **重试 1 次**，且只重试「暂时性故障」：超时、限流（429）、5xx。
  401 / 402 / 400 是配置问题（key 错了、余额不足），重试一次还是同样的错，
  只会让用户对着转圈白等
- **JSON 三层兜底**：直接 `json.loads` → 剥 ``` 代码围栏 → 正则取最外层 `{...}` / `[...]`。
  模型常见的毛病是 JSON 前后带一句「好的，以下是结果：」，第三层就是治这个的
- 三层都不成时，**重新调一次模型**（在提示词末尾补「只输出 JSON，不要任何解释」），
  **不是把同一段文本再解析一遍** —— 后者重试一百次也解析不出来。这条是用户特别确认过的

**`schemas/ai.py`（新）** —— `GeneratedCase` 的字段**刻意与 `TestCaseCreate` 对齐**，
这样「保存选中用例」可以直接复用现成的 `POST /projects/{id}/cases`，不用多加一个保存接口。

**`api/ai.py`（新）** —— 两个端点：

| 方法 | 路径 |
|---|---|
| POST | `/api/ai/generate-cases` |
| POST | `/api/ai/analyze-failure` |

- 每次调用（**含失败**）都落一条 `ai_task`：type / input / output / status。
  失败时 output 存模型最后一次的原始返回 —— 否则线上排查只剩一句「失败了」，
  看不到模型到底回了什么
- `ai_task` 表没有 project_id / case_id 字段，上下文一律写进 `input` 的 JSON 里
- **单条用例字段不合规就跳过、不连累整批**，少了几条在返回的 message 里明说
- 失败分析入参只有 `execution_id`，上下文由后端自己查执行记录拼（响应体截断到 2000 字符）

**`main.py`** —— 注册路由。⚠️ 新增路由模块必须挂 `dependencies=guard`，
否则它默认是**裸奔**的。这条已经写进 `CLAUDE.md`，验收里也加了断言专门盯它。

## 踩的坑

### 1. `app.routes` 里看不到 include_router 进来的路由

验收时想确认 AI 路由注册上了，`[r for r in app.routes if "/ai" in r.path]` 返回**空**。

原因：这一版 FastAPI 把 `include_router` 进来的路由包成了 `_IncludedRouter`，
`app.routes` 里只有它一个壳。**改查 `app.openapi()["paths"]`** 才看得到
（33 条路径里确实有那两条）。这条已经写进 `CLAUDE.md`。

### 2. 前端 axios 默认 30 秒超时，会先把 AI 调用掐断

后端给 DeepSeek 留了 60 秒，但前端 axios 默认 30 秒 —— 等于前端先放弃。
`api/ai.js` 里把这两个请求单独放大到 **180 秒**（留出后端 60 秒 × 2 次重试的余量）。

### 3. `case_type` 在「刚跑完」的那条路径上拿不到

`run_case` / `run_web_case` 直接返回 ORM 记录，没走 `execution_out()`，
所以没有 `case_type`。前端因此留了个兜底：拿不到该字段时用
「`result_json.steps` 是否为空」来判断 —— 这两种场景下它正好等价于类型。

### 4. Git Bash 传中文参数会被转成 GBK

`curl` 里带中文的 JSON body 到后端就成乱码。验收改成用 Python 脚本发请求、
把结果写成 UTF-8 的 JSON 文件再读回来。

## 两个口径上的取舍（都跟用户确认过）

### 1. 「AI 分析失败」按钮的显示条件

规格里写的是「仅接口执行显示」，实现成 **接口执行 + 状态为 fail / error**。

对一条**通过**的执行分析「失败原因」没有意义，而且旁边那个「提缺陷」本来就是
这个条件。用户确认采纳，与提缺陷保持一致。

### 2. AI 助手页里内联了一份弹窗逻辑

抽了 `AiGenerateDialog.vue` / `AiAnalysisDialog.vue` 两个公共组件给编辑页和执行详情用，
但 **AI 助手页里还是内联的**（那页先做完并已提交，没去动它）。

也就是「输入 → 生成 → 勾选 → 保存」这段逻辑现在有两份。用户选**方案 B：维持现状** ——
不影响功能，不动已验收过的代码，不引入回归风险。**记为本项目的已知技术债，后续可重构。**

## 三个安全点

### 1. 改密码这条路由，它所在的 router 本身是免守卫的

`auth.router` 在 `main.py:62` **没挂 `guard`** —— 它对全站豁免，因为 `/login`
必须免登录才能调。往这个 router 里加路由，**默认就是裸奔的**。

所以 `change_password` 自己声明了 `Depends(get_current_user)`，并在注释里写明原因。
验收里有一条断言专门钉它（无 token → 401）—— 这条断言的价值不在于它现在过不过，
而在于**将来谁把那个依赖删掉时会立刻红**。

### 2. 数据库地址回显，等于把库密码贴在设置页上

`settings.database_url` 长这样：

```
mysql+pymysql://root:test123456@127.0.0.1:3307/test_platform
```

这个字段是要渲染到页面上的，直接回显不只是「页面上看得见」——
它还会进浏览器历史、进截图、进验收日志。所以拆开之后**只回
scheme / host / port / 库名 / 用户**，密码那一节根本不往响应里放。

AI Key 同理：设置页只需要提示「配没配」，所以只回一个布尔值。
两条都加了断言（扫 `test123456` 和 `sk-` 这两个串）。

### 3. 验收里绝不能拿 admin 试改密码

改密码是**写操作**。要是拿 admin 试，脚本万一在中途异常退出，
admin 的密码就被改成别的东西了 —— 而 README、CHANGELOG、验收脚本里
到处写着 `admin123`，等于把下一次启动的人锁在门外。

所以全程用临时用户 `verify_tmp_user`：建 → 改 → 验新密码能登录、旧密码失效 →
`finally` 里删掉。另外单独加一条断言确认**这一轮没碰过 admin 的密码**。

## 一个设计取舍：改完密码不登出

后端改完密码**不吊销已签发的 token**，前端也**不强制退出登录**。

按安全洁癖应该踢下线。但这里的实际场景是：一个人正干着活顺手改了密码，
被自己的操作弹出登录页——收益（防住一个还没过期的 token）和体感损失不成比例。
旧 token 到期自然失效（默认 1440 分钟）。

## 一个没做到的：驱动版本号

原本想在驱动那行显示「Chrome 138.0.x」。**拿不到**：
`check_browser()` 是刻意做的廉价探测（只看可执行文件在不在、缓存目录能不能写），
**不启动浏览器也不下载驱动** —— 一旦启动，这一页首次打开就要卡几十秒。

要拿版本得跑一次 `chrome.exe --version`，而 Chrome 在 Windows 上根本不往
stdout 打版本号。所以页面显示的是**可执行文件路径**，那对排障其实更有用。
