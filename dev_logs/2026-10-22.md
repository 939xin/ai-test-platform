## 关键取舍
- **不复用 `execution` 表**：语义、状态机、统计口径都不同，混用会污染执行中心
- **不存每条请求明细**：只存聚合指标、直方图、时间线与最多 10 条错误样本
- **不做 Web UI 压测**：Selenium 成本远高于服务端请求，测到的是渲染成本
- **不引入图表库**：直方图与折线用纯 CSS / SVG 自绘，符合「只用 Element Plus」约束
- **单进程单活跃压测**：取消与实时进度依赖进程内注册表，文档已写明单 worker 前提

## 踩坑
- 直方图桶内插值可能越过真实 `max`（例如 p90=64 > max=63.59）。已在 `_build_metrics`
  里把百分位夹回 `[min, max]`，验收断言 `min ≤ p50 ≤ … ≤ p99 ≤ max` 才恒成立
- 运行中 `metrics_json` 为空，前端一开始把 duration 模式显示成「1000 次」、
  指标卡全是「—」。已改为运行中读进度接口的实时数据，模式回退读 `perf_run.load_mode`
- 停止接口返回的状态会停留在 `running`：manager 用自己的 Session 写 `stopping`，
  请求的 Session 还停在旧快照。已改为 `db.commit()` 后再 `refresh`
- 错误样本的消息里可能带完整 URL，已加二次脱敏（`token=…` 等参数值替换为 `***`）

## 验收扩面（同日追加 · 243 → 247）

修复单收尾后补了 4 条集成断言，钉住这一批新增的行为，防止下一个人改回去：

| 断言 | 钉住的行为 |
|---|---|
| `params_json` 真的发出去了（`$.delay_ms eq 42` 通过） | 用例 URL 写 `${base_url}/perf-target/echo`、参数放 `params_json`，响应体回显 42 才算通。这是「AI 生成用例」产品线的地基 —— 参数静默丢失会让 AI 生成的用例「看起来能跑、实际没带参数」 |
| 执行记录必达终态（`end_time` 非空、`status` 不是 `running`） | P0-2 的兜底链路：任何执行结束后历史记录都不能永远停在 `running` |
| 大响应体入库被截断（`result_json.response_truncated=true`） | P1-4 的 20 万字符上限真的生效了，而不是只写在配置里 |
| 报告文件名末段是 8 位十六进制随机段 | P1-8：文件名不可枚举，且随机段位于末尾，不能破坏 `_p{id}_` 解析与删项目清理 |
