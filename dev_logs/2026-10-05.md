# 2026-10-05 开发日志（Day 12）

## 今日目标

做 **Web 登录态复用**。

起因是一个架构问题：Web 用例执行时**每条都独立 `driver.quit()`**，所以登录后的功能
测试每条都要重新登一次。读代码核实——**确认如此**，而且全仓搜 `get_cookies` /
`add_cookie` / `storage_state` / `user-data-dir` **零命中**，一点复用机制都没有。

顺带发现 `execute_case` 其实**留了 `driver=` 入参**（`web_executor.py:771`），
还做了 `own_driver` 判断来区分"自建 vs 外部传入"——**但全仓没有任何一处传它**，
这个参数是死代码。等于当初留了共享的口子，没接上。

用户拍板的方案是 **B2：只搬登录态，不改 driver 生命周期** ——
仍然每条用例各起各的浏览器，只是把 cookie / localStorage 搬过去。

**明确不做**：不改隔离模型、不做并发、不动接口测试与 AI 模块。

分 7 步走，每步跑通再进下一步。

## 第 1 步：数据模型 + 幂等补列助手

### 先撞上一件事：`create_all` 不给已有表加列

`main.py:24` 用的是 `Base.metadata.create_all()`。它只建**缺失的表**，
对已有表新增的**列**完全视而不见。注释里写着"表结构稳定后换 Alembic"，
但 **Alembic 从没引入**。

后果是分层的：

- 新建 `web_session` 表 → 启动自动建，**零操作**
- 给 `test_case` 加两个标记列 → **不会自动加**，已有库会直接报 `Unknown column`

所以两个标记不能只写进模型就完事。

### 做法

`database.py` 加了 `ensure_schema()` = `create_all` + **幂等的列检查**：

```python
_ADDED_COLUMNS: dict[str, dict[str, str]] = {
    "test_case": {
        "login_case": "TINYINT(1) NOT NULL DEFAULT 0",
        "needs_login": "TINYINT(1) NOT NULL DEFAULT 0",
    },
}
```

只写「追加到表尾、带默认值」的形式——MySQL 8 对这种 ALTER 走 **INSTANT 算法**，
只改元数据，不重建表也不锁表。

**为什么不做成自动比对模型差异的通用版本**：那要自己从模型编 DDL，遇到
`NOT NULL` 又没有 `server_default` 的列会直接炸在非空表上。显式登记难看一点，
但每一条 DDL 都是人写下来、能审的。

**顺带说明**：这仍是过渡手段。往已有表加字段要登记到 `_ADDED_COLUMNS`，
表结构再稳定些应整体换 Alembic——这条已经写进 `CLAUDE.md`。

### 验收

- 连跑两次 `ensure_schema()`：第一次补两列，**第二次一条 ALTER 都没发**
- 库结构核对：`test_case.login_case` / `needs_login` 存在，`web_session` 建成
  （11 → **12 张表**）
- `verify_all.py` **184/184**

## 第 2 步：`web_session.py` + 执行器改造

### 注入的四步顺序是硬性的

```
1. driver.get(origin)          ← 跳板，必须先到目标域
2. add_cookie
3. JS 写 localStorage / sessionStorage
4. 才轮到用例自己的第一步（通常是 open_url）
```

第 1 步不是优化，是**前提**：浏览器只允许在目标域上写 cookie 与 storage，
在空白页上 `add_cookie` 会被**静默丢弃**——不抛异常、也不生效。这是最难查的那类失败。

同源的前提下，第 4 步的导航不会把第 2、3 步写进去的东西弄丢——这正是方案能成立的原因。
**但如果用例第一步跳去别的域名，注入必然失效**，那是浏览器规则，界面上写明了。

### 两个坑，实测复现过才写的清洗逻辑

`_clean_cookie()` 处理两件事，都是我先构造出问题输入、真跑一遍才确信的：

```
未清洗直接 add_cookie -> AssertionError
未清洗直接 add_cookie -> InvalidArgumentException: invalid 'expiry'
清洗后 add_cookie -> OK
```

1. **`sameSite`**：Selenium 只认 `Strict` / `Lax` / `None`，而且用的是 **`assert`**
   而不是返回错误——Chrome 对没显式声明的 cookie 会给 `'unspecified'`，原样喂回去直接崩
2. **`expiry`**：必须是**整数秒**，浮点会被拒

### 往返验证

全新 driver 注入后导航到真实页面，**浏览器自己读到**：

```json
{ "cookie": "sid=abc123; theme=dark",
  "ls_token": "jwt-xyz", "ss_tmp": "sess-1" }
```

### 顺带修 `${base_url}`

`ACTION_SPEC` 里 `open_url` 的字段提示写着「可含 `${变量}`，如 `${base_url}/login`」，
但 `web_executor.py:816` 只注入了 `variables_json`——**那句话根本兑不了现**：
占位符不被替换，浏览器会去访问字面量 `"${base_url}/login"`。

### ⚠️ 写坏过一次，是冒烟测试抓住的

改 `web_executor.py` 时我**误删了 `shot_dir` / `shot_root` 两行**（替换代码块时
起止没对齐），导致每次 Web 执行都 `NameError`。

### ⚠️ 更要紧的：第一次跑的「184/184」是假的

修完代码我跑了一遍验收，报"无回归"。但**后端进程还是第 1 步时启动的，
加载的是旧的 `web_executor.py`**——第 2 步的改动根本没被执行到，**那次 184 项
一项都没测到新代码**。

是后来单独跑 `${base_url}` 检查时直接抛 `NameError` 才暴露。

**教训：改了执行器必须重启后端再验收，否则验收结果毫无意义。**
后面每步都固定「改完 → 重启 → 验收」这个顺序。

## 第 3 步：查看 / 清除登录态的两个接口

`GET` / `DELETE /api/projects/{id}/web-session`，照 `datasets.py` 的样板写，
注册时挂 `dependencies=guard`。

两个刻意的选择：

- **没有登录态时返回 `null` 而不是 404**。「新项目还没登录过」是这个资源的正常状态，
  不是错误；用 404 会逼着前端把"还没配"和"接口挂了"写成同一段处理
- **摘要只回 storage 的 `key`、不回 `value`**（那些 value 就是令牌），
  和设置页数据库密码脱敏同一个口径

验收 10 项，其中特意往库里塞了三个带 `SECRET-` 前缀的值，确认
**接口摘要里一个都没出现**。

## 能力边界（不要过度承诺）

### 1. 登录态是否过期，程序无法可靠判定

cookie 的到期时间读得到（`expires_at`），但 **localStorage 里的 JWT 何时失效，
前端不暴露任何信号**；而且"被重定向到登录页"各家站点表现都不同。

所以目前只做到「cookie 到期就在界面上提醒一句」，**不参与任何执行决策**。
真要根治得让用户能配一条轻量的"校验登录态"探测用例。

**不假装能自动检测过期**——这是这次特意守住的一条线。查出个假的"状态正常"
比不查更糟。

### 2. 跨域注入天然无效

用例第一步若跳到别的域名，注入一定不生效。这是浏览器的同源规则，不是 bug，
界面上已写明。

### 3. 库里存的 cookie 等价于会话令牌，是明文

**测试工具场景可接受，生产环境必须加密**（至少整表加密或改用 KMS 托管）。
这条写进了 `CLAUDE.md`。同时做了两件事降低暴露面：执行记录里不落明文
（导出走 `_captured_session` 私有键，落库前 pop 掉）、接口摘要只回 key 不回 value。
