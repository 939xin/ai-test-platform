# 面试问答准备

> 面试官可能会问的核心问题，提前准备好回答

---

## Q1: 这个项目你做了多久？几个人做的？

**答**：独立全栈开发，从需求分析、架构设计、编码实现到测试验证，核心功能约 2 周完成。后续持续迭代优化。

## Q2: 为什么不用现成的工具（Postman/JMeter）而要自己写？

**答**：最初是用 Python 写脚本做自动化，但脚本维护成本高、测试人员用不了。这个工具把脚本能力封装成 GUI，测试人员点点鼠标就能执行测试、查看报告。同时我发现市面工具很难同时管接口测试和 Web UI 测试，所以自己做了统一平台。

## Q3: 和同类工具比你的优势是什么？

**答**：
1. **双引擎一体**：接口测试和 Web 测试共享环境管理、变量系统、报告体系，不用切工具
2. **启动即用**：SQLite 本地数据库 + PyInstaller 单文件 .exe，解压即可，不用配数据库和服务器
3. **透明的执行过程**：调试模式开浏览器窗口让用户看着操作，且每条用例的请求/响应数据完整可追溯
4. **低耦合可扩展**：MVC 架构 + QThread 异步，后续加新测试类型（如 gRPC）不用动现有代码

## Q4: 遇到过什么技术难题？怎么解决的？

**几个印象深刻的问题：**

**① QThread 内 HTTP 请求异常中断**
- 现象：主线程发请求正常，但放入 QThread 后收不到响应
- 排查：逐层剥离测试，用 5 步对比脚本定位到 `requests.request()` vs `requests.post()` 调用差异
- 解决：从 `**kwargs` 字典展开改为直接调用 `requests.post/get`，超时从 30 秒改为 10 秒

**② pytest 子进程架构导致测试结果失真**
- 现象：所有用例共用一个 exit code，错误数据也显示通过，请求/响应数据不写入报告
- 排查：跟踪数据流发现 `_save_results_to_db` 只写 `test_results`，从不写 `test_result_details`
- 解决：废弃 pytest 子进程模式，改为进程内直接 requests 调用，逐条执行逐条断言逐条入库

**③ Qt6 QSS 不兼容内联 SVG**
- 现象：复选框勾号显示为纯蓝色方块
- 排查：手写对比测试确定 Qt6 不支持 `data:image/svg+xml` 内联
- 解决：创建独立 check.svg 文件，用绝对路径引用

## Q5: 项目有哪些不足？如果重做会怎么改进？

**答**：
1. 应该从第一天就用依赖注入和接口抽象，引擎层不应该直接调用 DBManager（现在引擎和数据库耦合）
2. 测试类型的注册机制应该做成插件模式，加新类型不用改框架代码
3. 缺少 CI/CD 集成，如果做 v2 会加命令行模式支持 Jenkins 调用

## Q6: 数据模型为什么设计 10 张表？

**答**：核心需求是"测试用例持久化"+"执行结果可追溯"。一张主表存用例配置，子表存 headers、断言、步骤、定位器、结果详情和截图。好处是：① 用例编辑时子数据用事务重写 ② 报告渲染查一次主数据+一次详情就能拼完整

## Q7: 95 项自动化验证覆盖了什么？

**答**：覆盖了数据库 11 张表的 CRUD、环境管理边界值（特殊字符/空名称）、变量解析器、脚本生成器（接口+Web）、API 引擎代码生成（含特殊字符测试名）、WebRunner 步骤描述生成、HTML 报告结构检查（DOCTYPE/样式/截图嵌入/footer）、所有 5 个 UI 组件的创建和页面切换
